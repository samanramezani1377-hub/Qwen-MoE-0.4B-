# تصمیم‌های فنی پروژه

## 2026-10-25 — شروع ممیزی

- مدل مرجع/معلم: `Qwen/Qwen3.5-2B`.
- پیکربندی زندهٔ Hub با معماری `Qwen3_5ForConditionalGeneration` و `text_config` شامل ۲۴ لایه، hidden size برابر ۲۰۴۸، intermediate size برابر ۶۱۴۴ و vocabulary برابر ۲۴۸۳۲۰ تأیید شد.
- لایه‌های متن ترکیبی از `linear_attention` و `full_attention` هستند.
- جدول embedding مشترک مرجع: `2048 × 248320 = 508,559,360` پارامتر؛ این تعداد پارامتر جدول است و نباید بدون تعریف شمارش با پارامتر فعال هر توکن یکی گرفته شود.
- مرحلهٔ اولیه فقط ممیزی config است و وزن‌ها را دانلود نمی‌کند.
- هیچ GPU یا سرویس پولی بدون تأیید کاربر اجرا نمی‌شود.

## 2026-10-25 — تثبیت هدف جدید و بودجهٔ موبایل

- هدف کاربر: حدود ۵۰۸٫۶ میلیون پارامتر فعال در هر توکن؛ تعداد کل مدل می‌تواند بیشتر باشد؛ اجرای آفلاین اندروید اولویت دارد.
- هدف قدیمی «حداکثر ۰٫۴B پارامتر کل» دیگر معیار اصلی نیست. نام مخزن `Qwen-MoE-0.4B` فعلاً برای سازگاری با آدرس مخزن حفظ شده است.
- طرح محاسباتی اولیه: ۲۴ لایه، hidden size=1024، vocabulary=248320، embedding/LM head مشترک، ۱۸ لایه linear attention و ۶ لایه full attention، ۸ متخصص در هر لایه، top-2، expert intermediate=1280.
- برآورد اولیه: حدود 506.6M پارامتر فعال در هر توکن و حدود 1.073B پارامتر یکتا؛ این‌ها تخمین‌های معماری‌اند، نه شمارش از یک مدل پیاده‌سازی‌شده.
- اندازهٔ نظری وزن‌های INT4 برای 1.073B پارامتر حدود 0.54 GB است، پیش از سربار scale/metadata/runtime/cache. هزینهٔ خروجی logits روی 248,320 توکن و پشتیبانی runtime برای hybrid attention/MoE همچنان ریسک مهم موبایل است.
- کوچک‌سازی hidden size از 2048 به 1024 یعنی انتقال مستقیم تمام وزن‌های معلم ممکن نیست؛ باید تبدیل ابعاد/فشرده‌سازی و تقطیر دانش ارزیابی شود.
- جزئیات فرمول‌ها و بودجه در [docs/ARCHITECTURE_BUDGET.md](ARCHITECTURE_BUDGET.md) ثبت شده است.
- هیچ مدل مقصدی هنوز ساخته، آموزش یا روی اندروید بنچمارک نشده است.

## دروازه‌های قبل از ساخت کامل

1. تثبیت revision دقیق config و tokenizer و بررسی نسخهٔ Transformers سازگار.
2. ساخت config مقصد و تست forward محدود؛ ابتدا با وزن‌های تصادفی و بدون دانلود کل معلم.
3. تأیید امکان اجرا روی CPU/Android برای linear attention و MoE.
4. اندازه‌گیری واقعی تعداد کل/فعال، RAM، اندازهٔ quantized و سرعت.
5. فقط بعد از موفقیت نمونهٔ محدود، ادامهٔ انتقال وزن/تقطیر و آموزش.
